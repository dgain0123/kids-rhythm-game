# 踩過的坑（除錯筆記）

一路遇到的問題與最終解法，避免重踩。

## 麥克風
- **Mac mini 沒內建麥克風** → 系統輸入完全沒訊號，別誤判成權限/程式。先 `system_profiler SPAudioDataType` 看有沒有實體輸入(虛擬的 Teams/Zoom 不算)。要接外接麥克風。
- **開麥克風的初始化爆音**被算成一下 → 加 `warmupMs=600` 暖機期忽略。
- **快速打兩下只算一下** → `refractoryMs` 太長(400ms)把第二下吃掉，改 130ms，防餘音改靠遲滯武裝。
- **換關量表全 0** → `resume()` 沒喚醒被 suspend 的 AudioContext；串流死掉沒重開。已修，並加「重連麥克風」按鈕。
- **麥克風常當掉**：外接 3.5mm 易接觸不良；多個瀏覽器分頁搶麥克風也會卡；可 `sudo killall coreaudiod` 重啟音訊引擎。

## 音效（Safari 最麻煩）
- **過關沒歡呼、失敗有**：Safari 自動播放限制——麥克風觸發(非點擊)的 `<audio>` 被擋。解法：開始遊戲點擊時 `primeCheer` 靜音播一下解鎖元素。
- **Web Audio 在此機無聲**：改用 `<audio>` 元素播真人音效。
- **歡呼中間斷一下**：曾因(1)過關 close 麥克風→macOS 重設裝置閃斷(改 pause)、(2)彩帶 fillText 數百 emoji 卡主執行緒(改 sprite+延後)。
- **離線過關沒聲、失敗有**：大檔 `<audio>` 發範圍請求，離線快取只回完整檔→Safari 拒絕。解法：音效改 **blob 整包載入記憶體**播放，不再發網路/範圍請求；SW 另加範圍請求回 206 當保險。

## 版面 / UI
- **畫面捲不動、標題被切**：曾用垂直置中+overflow hidden；改 `flex-start`+可捲動+一律顯示捲軸。
- **快取一直給舊版**：改用禁快取 `serve.py`；瀏覽器仍頑固時清網站資料。
- **號碼牌蓋住角色**：改直式(號碼在上、角色在下)；兔子特例放兩耳正中上方。
- **用截圖驗證版面**：Playwright(webkit=Safari 引擎)開本機頁、截 `#face`/`#stage`，或 `getBoundingClientRect` 量實際座標——不靠肉眼猜。

## 部署 / 快取
- **改了線上卻沒變**：GitHub Pages 建置 + CDN 傳播要數分鐘。先 `curl` 線上檔確認含新內容、`gh api .../pages/builds/latest` 確認 build=built，再叫使用者重整。
- **Service Worker 更新**：常要載入一次才切換，重整 2 次或清網站資料。
- **serve.py 單執行緒卡死**：瀏覽器並發請求會卡（Playwright 會逾時），改 `ThreadingHTTPServer`。

## 跟拍關卡音樂在網頁裡卡頓(2026-07-28，已解)
- 症狀：音樂檔 afplay 直接播乾淨，遊戲網頁裡播就斷斷續續。
- 根因：`<audio>` 元素在這台 Safari 會被「頁面主執行緒忙碌」切到(麥克風偵測+每幀畫布+DOM更新)，
  與過關歡呼斷音同病。主執行緒瘦身(節流/降fps)仍不夠。
- 解法：跟拍音樂改 **Web Audio AudioBuffer** 播放(`getCtx().decodeAudioData` + BufferSource)，
  在獨立音訊執行緒渲染，主執行緒卡也不影響；時鐘同步改用 `audioCtx.currentTime - musicT0`。
  手動停止前要先拔 `onended`(否則會誤觸發「歌放完」失敗判定)。

## 數拍人聲 one/four 永遠卡卡(2026-07-28，已解)
- 症狀：換了幾個 TTS 聲源，使用者都說「1 跟 4 卡卡的」，two/three 沒事。
- 根因：one 開頭是 /w/ 滑音、four 開頭 /f/ 氣音+尾巴長 /r/，都是**軟邊緣**，
  靜音門檻修剪會切進它們；two(t)/three(th) 開頭尖銳所以怎麼剪都聽不出來。
  另外 one 排在音檔第 0 秒，正好撞上播放起頭的暫態。
- 解法(tools/voice_count.py)：**完全不修剪字的頭尾**(只去純零 padding)，
  改偵測「起音點」把字對齊拍點；音檔最前面加 1 秒靜音緩衝(chart.preRollSec，
  倒數大字從緩衝後才開始數)。教訓：處理人聲別用靜音門檻硬剪。

## 跟拍音樂卡頓最終破案(2026-07-28)：Safari「原始模式麥克風」害的 → 改走語音處理路徑，已解
- 完整排查鏈：檔案 afplay 乾淨→網頁卡；主執行緒瘦身沒用；改 Web Audio buffer 沒用；
  `?nomic=1`(不開麥)乾淨→開麥就卡；ffmpeg 佔用麥克風+afplay 同播＝乾淨(麥克風硬體無罪)；
  Chrome 開同一個遊戲＝乾淨 → 元兇是這台 Mac mini 的 Safari「getUserMedia+播放」組合。
- **最終解(js/audio.js)**：getUserMedia 從「原始模式」(echoCancellation/noiseSuppression 全關)
  改成**語音處理路徑(兩者都開)**＝視訊通話同款、Safari 最成熟的路徑 → 音樂不抖、打鼓照樣偵測，
  回音消除還附帶把喇叭音樂從麥克風訊號扣掉(不易誤觸發)。`?micmode=raw` 可切回原始模式對照。
- 沿路留下的東西都有價值：Web Audio buffer 播放(更穩)、?nomic=1 診斷開關、
  人聲不修剪+起音對齊+preRollSec(檔案本身也更乾淨)。
- 教訓：**排查「播放卡頓」先做二分實驗**(不開麥/佔用麥/換瀏覽器)再動手改，能省掉好幾輪瞎修。

## 音訊母帶與量測（2026-08-03，踩很久）

- **峰值正規化會讓動態大的曲子整首變小聲**：峰值被節拍器的短促尖峰佔走 →
  第20關比第一大關卡小 **7 dB**（RMS -23.4 vs -16.4，但兩邊峰值都 0.85）。
  → 音量要用 **RMS/響段響度**比，不能用峰值。
- **壓縮是「雜訊感」的元兇**：把 14.7 dB 的 crest factor 壓成 6.7 dB，還把預備拍人聲的
  mp3 編碼雜訊一起抬起來。使用者一聽就抓到。→ 現在母帶**只調音量、零壓縮**
  （`Mixer.finish(clean=True)`，全域 `CLEAN_MASTER`）。
- **不壓縮就只能大到峰值頂到 1.0 為止**：從 0.89 推到 0.97 只多 **0.9 dB**，就到頂了。
  想更大聲只能轉喇叭——「跟提示音一樣大聲」本來就是壓縮換來的，兩者不可兼得。
- **量峰值一定要用「原生取樣率＋float」**：
  - 降取樣（8k/22k）的濾波器**自己會過衝** → 假破表（level14 原生 0.977、8k 量成 1.097）。
  - `s16le` 解碼會把超過 1.0 的值**夾在 1.000**，看不出真實過衝。
  - 立體聲別用 `ffmpeg -ac 1` 量：它的降混會**相加**（歡呼被量成峰值 1.39、響段少差 3 dB），
    要自己算 `(L+R)/2`。
- **AAC 編碼會過衝，且過衝量因素材而異**：壓縮過的密實訊號過衝大（0.80+128k → 解碼 1.02）。
  → `Mixer.finish` 編碼後會**解碼回來驗峰值，破表就自動降一點重編**。
- **改音量標準時不要「重新合成」而要「重跑產生器」還是「母帶重製」要分清楚**：
  壓縮是破壞性的，只調音量救不回動態 → 要**重跑產生器**；
  單純換音量水位（內容不變）→ 用 `tools/remaster_music.py` / `remaster_sfx.py`。

## 現成音樂來源（2026-08-03 實測）

- **Freesound 是「音效庫」不是「配樂庫」**：CC0 很多但都是使用者上傳的音效片段，
  拿來當背景音樂會被嫌難聽（使用者實際打槍過）。
- **Jamendo**（Openverse 加 `license=by` 就能查）才是音樂人的完整作品；
  **incompetech**（Kevin MacLeod, CC BY 4.0）是專業配樂庫、節奏極準、可直連下載。
- **Pixabay 不能用**：擋自動抓取，且授權**禁止把原檔原樣再散布** → 跟公開 repo 衝突。
- **archive.org 上標「公共領域」的兒歌專輯多半是翻錄商業唱片亂標**，別碰。
- **公共領域旋律 ≠ 錄音也是公共領域**：小星星/搖籃曲旋律是公版，但**某個演奏版本的錄音**
  仍可能有版權。要看錄音的授權。
- **實錄一定有房間殘響**，去空間感（向下擴張）只能壓小、壓不掉。要「跟程式合成一樣乾淨」
  就只能自己 render → 這是 AI 會議室 5 人一致的結論（記錄：`AI會議室/記錄/會議_20260803_0932.md`）。

## 節拍相關（2026-08-03）

- **`librosa.beat.beat_track` 對連續音色（管風琴）會抓錯拍**：實測把 97.2BPM 抓成 95.5，
  還會跳節拍層級。→ `tools/track_music.py` 改用「起音包絡自相關 + 梳狀相位精修」。
- **「拍點對不上」先懷疑 Service Worker 快取**：舊音樂配新譜（或反過來）拍點就會整個錯開，
  重整兩次就好。使用者回報過一次「完全不一樣」，重整後即正常。

## 音訊對齊與收尾（2026-08-14）

- **量拍點對齊不要用能量包絡/帶通 onset**：樂器（馬林巴/吉他）在 click 頻段的透染
  會搶峰，量出 50~120ms 的**假抖動**，差點誤判「第三章沒對齊」。
  正解＝**木魚 click 波形匹配濾波**（程式擺位真值 0.0ms；已釘 golden：
  `test_click_alignment_golden`，每關每一拍 ≤15ms）。
- **終止音給固定 0.3 秒聲頭，快速關卡會混進下 1~2 個拍點的音**（速度100 的拍點
  間隔才 0.15 秒）→ `end_at_last_hit` 的 hold=min(0.12s, 0.7×拍點間隔)，
  保證切在下一個拍點音之前。
- **弦樂墊(swell)愈大聲、慢速素材整段反而愈小**：pad 的 swell 峰值頂到 CLEAN_PEAK，
  乾淨母帶等比例縮小 → hit6s 用力度 68 量出 -16.0dBFS、62 才 -13.2。
  → 墊底力度每個速度各自實測（`make_twinkle_render.py` 的 `PAD_VEL` 表）。
- **畫面比聲音早幾十 ms**：`ctx.currentTime` 是「正在渲染」的時刻，喇叭出聲還要晚
  outputLatency；且 `start()` 不帶時刻會晚幾 ms 且不定 → `musicNow()` 扣輸出延遲
  ＋`start(musicT0)` 排準起播（釘樁 `test_audio_clock_sync_rules`）。

## 幼兒版面（2026-08-03）

- **角色超過 8 隻會擠出畫面**：第19關要 12 隻時，左右各有幾隻被切在螢幕外。
  → `#face.many`（`charCount > 8` 時由 `characters.js` 掛上）改成可換行的縮小版，
  桌機一排 6、手機（≤620px）一排 4。
- **三連音符頭會疊在一起**：1/3 拍在原本 64px/拍的密度下只隔 21px，符頭寬就 25px。
  → `MIN_NOTE_PX=32`：音符很密的譜每拍自動畫寬一點（八分以上算出來剛好是原密度，舊關卡不變）。
